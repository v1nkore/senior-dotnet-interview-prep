# Подготовка к офферу Senior .NET · и смена работы

Всё в одной папке. Три слоя: **теория → практика → поиск работы**.

```
~/interview
├── 200_ответов_Senior_NET.html        ← теория: 200 вопросов, 17 разделов (разборы ответов)
├── Тест_100_вопросов_Senior_NET.html  ← самопроверка: вопросы 1–100, 4 варианта, с приоритетом
├── Pet-проекты_и_чеклисты.md          ← маршрут: раздел → проект → пункт чек-листа, с отметками
├── dotnet-petprojects/                ← практика: 14 проектов (git)
│   ├── index.html                     ← открыть в браузере, навигация по проектам
│   ├── recruiter-screening-qa.html    ← скрининг рекрутера
│   ├── architecture-map.md            ← паттерн → проект → файл/класс
│   └── <14 проектов>/README.md + study-guide.html
├── LeetCode.Practice/                 ← 23 алгоритмические задачи (git)
└── job-search/                        ← поиск работы
    ├── account-context.md             ← о себе: стек, опыт, цели, контакты
    ├── Резюме/[имя].docx
    ├── Сопроводительные/
    │   ├── Сопроводительное.txt               ← базовое, подставляется в hh-autoapply
    │   └── Сопроводительное_шаблон_под_вакансию.txt
    └── hh-autoapply/                  ← автоотклики на hh.ru (git, ASP.NET Core + Playwright)
```

## С чего начать

1. **`Тест_100_вопросов_Senior_NET.html`** — пройти первым, до повторения. 100 вопросов, по четыре варианта,
   расставлены по приоритету. Даёт точный список дыр вместо ощущения «всё забыл».
   Отвечай не открывая `200_ответов`, иначе смысла нет.
2. **`200_ответов_Senior_NET.html`** — разборы ответов. Ищи по номеру вопроса из теста.
3. **`Pet-проекты_и_чеклисты.md`** — маршрут по разделам с чекбоксами. Отмечаешь `[x]` по мере разбора.
4. **`dotnet-petprojects/index.html`** — навигация по проектам, кнопки «Study-guide» и команды запуска.
5. **`job-search/account-context.md`** — контекст для сопроводительных писем и ответов на скрининге.

## Как читать приоритеты в тесте

| | Значение | Что делать с провалом |
|---|---|---|
| **P0** | Спрашивают почти всегда (48 вопросов) | Тему поднимать заново, а не повторять |
| **P1** | Часто, но не всегда (46) | Добирать после P0 |
| **P2** | Редко или на углублении (6) | Только если лезешь вглубь темы |

Итог считается прежде всего по P0: если в P0 провалов нет — база рабочая и повторение имеет смысл.

## Ритм

Один проект = одна волна в 1–2 недели. После разбора — конспект «что понял» в 5–10 строк своими словами. Параллельно собеседования: поплыл на вопросе → пункт в план следующей недели.

Повторение — не перечитывание, а попытка достать ответ без источника. Тест для этого и нужен: провалился — иди читай разбор этого вопроса, а не весь файл подряд.

## Что нужно на машине

Проверено, всё на месте: .NET SDK 10.0.400, `dotnet`, `docker`, `kind`, `helm`.

`docker compose up -d` требуется в трёх проектах: `dotnet-petprojects/EfCoreLab/`, `dotnet-petprojects/OrderFlow/`, `dotnet-petprojects/RedisLab/`. Остальные запускаются без инфраструктуры.
