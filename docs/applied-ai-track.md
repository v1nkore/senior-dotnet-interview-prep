# Прикладной AI-трек для .NET backend

Добавлено 27 октября 2026 по итогам разбора видео [«Разработчик в 2026: новый roadmap и путь к AI Engineer»](https://www.youtube.com/watch?v=DWSohA-k6vA). Это обязательный двадцатый блок общей подготовки Senior .NET + Applied AI. Он не заменяет инженерную базу, распределённые системы, тестирование и эксплуатацию, а проверяется вместе с ними.

## Что уже покрыто основной программой

- API, OAuth/OIDC, секреты и разграничение доступа;
- PostgreSQL, индексы, очереди, retry, идемпотентность и backpressure;
- Docker, Kubernetes, CI/CD и наблюдаемость;
- тестирование, безопасность и system design.

Поэтому эти темы не повторяются отдельно. Ниже — только AI-специфичные знания и практика.

## Результат трека

Нужно уметь спроектировать и защитить прикладную AI-функцию в .NET-сервисе: выбрать модель, управлять контекстом, получить структурированный ответ, построить RAG, безопасно вызвать инструменты, измерить качество и эксплуатировать решение по SLO, стоимости и рискам.

## Модули

### 1. LLM, контекст и API

- модель как вероятностная зависимость, а не детерминированная бизнес-функция;
- tokens, context window, temperature и причины недетерминизма;
- выбор модели по качеству, latency, стоимости, ограничениям данных и tool calling;
- облачные и локальные модели, provider abstraction и переносимость;
- structured outputs по JSON Schema, валидация и безопасный разбор ответа;
- prompt templates, версии промптов и отделение инструкций от пользовательских данных.

### 2. Данные и RAG

- ingestion и повторная индексация изменившихся документов;
- chunking, overlap, metadata и наследование прав доступа;
- embeddings и similarity search;
- PostgreSQL + `pgvector` как стартовый вариант хранения;
- hybrid search: полнотекстовый и векторный поиск;
- reranking, цитаты, freshness и борьба с нерелевантным контекстом;
- отличие RAG от fine-tuning и обычного поиска.

### 3. Tool calling, MCP и агенты

- схема инструмента, валидация аргументов и возврата;
- состояние, краткосрочная память и граница между workflow и автономным агентом;
- timeout, retry, idempotency и восстановление после частично выполненного действия;
- least privilege для инструментов и подтверждение опасных действий человеком;
- MCP как протокол подключения контекста и инструментов, а не как «магия агента»;
- Agent SDK как основной практический вариант; LangGraph — для понимания графовой оркестрации, без обязательной смены языка.

### 4. Проверка качества

- golden dataset из реальных и граничных запросов;
- метрики retrieval: recall@k, precision@k и MRR;
- метрики ответа: корректность, groundedness, полнота, формат и безопасность;
- детерминированные проверки до LLM-as-judge;
- ограничения LLM-as-judge, калибровка человеком и воспроизводимость;
- offline evals, online-метрики и регрессии в CI при смене промпта, модели или индекса.

### 5. Эксплуатация и безопасность

- trace: запрос → retrieval → model → tool; latency и token usage каждого шага;
- стоимость запроса, rate limits, budget limits, caching и выбор дешёвой модели для простых шагов;
- fallback, circuit breaker и деградация без AI-функции;
- prompt injection, indirect prompt injection и data exfiltration;
- разделение инструкций и данных, allowlist инструментов и проверка результата;
- PII, retention, audit и запрет секретов в промптах и трассах.

### 6. Работа разработчика с агентами

- контекст проекта и короткая спецификация до генерации кода;
- цикл `plan → implementation → review → tests → evals`;
- проверка diff, зависимостей, миграций, безопасности и эксплуатации;
- правила репозитория и минимальные полномочия агента;
- агент ускоряет реализацию, но ответственность за корректность остаётся у инженера.

## Практика: AiAssistantLab

Минимальный проект — .NET API помощника по внутренней документации.

1. Принимает вопрос и возвращает JSON по фиксированной схеме с цитатами.
2. Индексирует документы в PostgreSQL + `pgvector`, хранит metadata и ACL.
3. Выполняет hybrid retrieval и опциональный reranking.
4. Имеет один read-only tool и одно действие, требующее подтверждения человеком.
5. Хранит версии промпта, модели и индекса в trace.
6. Запускает eval-набор в CI и блокирует явную регрессию.
7. Считает latency, tokens и приблизительную стоимость запроса.
8. Содержит тесты на prompt injection, утечку чужих документов и повтор tool call.

## Критерий завершения

- два самостоятельных ответа по каждому из пяти технических модулей в разные дни;
- архитектурный разбор AI-функции с оценкой качества, стоимости и угроз;
- работающий вертикальный срез `ingestion → retrieval → answer → eval`;
- один разбор инцидента: плохой retrieval, рост стоимости, утечка данных или повторное действие агента.

## Место в расписании

Блок встроен в обязательный [месячный план](month-plan.md), но идёт строго после прежней технической программы: учебные дни 19–24, 24 из 96 часов. До этого AI-вопросы в интервью не подмешиваются. Этап завершается работающим `AiAssistantLab`. Python и TypeScript изучаются только до уровня чтения примеров и SDK; основной стек остаётся на .NET.
